# DSH

一个**直连 DeepSeek API 的聊天客户端**，纯静态、无后端、无构建步骤。可部署到 GitHub Pages，在 iPhone 上用 Safari「添加到主屏幕」后像普通 App 一样全屏启动。

## 功能

- 多轮对话，会话历史保存在本机
- **流式输出**：逐字返回
- **深度思考**：单独折叠展示模型推理过程（`reasoning_content`）
- **图片输入**：从相册选图或直接拍照，发送前自动降采样
- **文档读取**：读取 txt / 代码 / docx / pdf，提取文字后作为上下文
- **把结果存回手机**：AI 生成的代码可一键走系统分享面板「存储到文件」
- 停止生成、复制回复、删除会话
- 模型切换：`deepseek-flash`、`deepseek-v4-pro`
- 离线可打开界面（对话本身需要联网）

## 图标

应用图标是鲸鱼（DeepSeek 也是鲸鱼）。设计上刻意避开了"看起来像鱼"的画法：

- **钝圆的大头**而不是椭圆身体（椭圆 + 对称叉尾就是鱼，这是第一版的错误）
- **下颌线**：一条挖空的弧线，鲸类的辨识度主要来自这里
- **细尾柄 + 后掠的圆润尾鳍**：鱼的尾鳍是对称尖叉，鲸的尾鳍厚实、圆润、向后掠
- **胸鳍**：用旋转椭圆画，形状圆润且必然与身体重叠，不会有接缝
- **喷水**：用一组水珠而不是实心水柱 —— 实心月牙会被误读成鳍或叶子

尺寸上做了区分：**小尺寸（顶栏 26px / 头像）不带喷水**，几像素的水珠只会糊成一团；**大尺寸（欢迎页 84px、应用图标）才带上**。

应用内的标识用 `fill-rule="evenodd"` 把眼睛和下颌线**挖空**，所以能自动透出底板色；底板的 `fill` 绑定 `--accent-deep`，**换主题时会跟着变色**。图标本身（`icon.svg` / PNG）是静态的、不能跟随主题，用的是默认「素白」主题的深板岩色，不含青色。

> PNG 图标由 SVG 栅格化而来：先用无头 Edge 渲染 1024px 全出血版，再用 `System.Drawing` 高质量降采样到 180 / 192 / 512。iOS 会自己裁圆角，所以给它的 PNG **不能带圆角或透明**。

## 主题配色与特效

**默认是浅色（白色）主题。** 设置里可以切 `浅色 / 深色 / 跟随系统`，10 组预设配色（5 浅 5 深），以及**两个取色器**——任意两种颜色都能混搭。色板做成了迷你预览：外壳是页面底色（一眼区分浅色 / 深色主题），里面才是双色渐变。

### 换色要"明显"，关键不是改强调色

前一版只改了强调色，结果换色几乎看不出来 —— 因为强调色只出现在按钮、图标那几个小面积上，**大部分像素是固定的背景与面板**。现在所选颜色会混进整页背景和面板，整屏都会跟着变。

但这里有个本质矛盾：**浅色主题的底要白，就不能染太深**。所以分层处理：

- 底色只带一点点色相（保住"白"）
- 颜色主要交给**大面积的柔光斑**和玻璃面板去表现

实现上是**取主色的色相、保留基线色的明度、按比例缩放饱和度**，而不是直接混色 —— 直接把深色主色混进白底会变成灰，"素白"就不白了。

### 颜色不能直接套用，必须反推

- 亮色按钮上配白字读不清（亮青 `#12c4c9` 配白字只有 **2.9:1**），所以字色要按对比度**自动选深或浅**
- 任选一个中间调（比如 `#808080`）时，**两种字色都到不了 4.5:1**，所以还必须能**自动挪底色**：
  - 按钮底色朝字色的反方向推进，直到达标（`ensureContrast`）
  - 气泡底色从主色压暗，直到白字达标（`readableOn`）

实测 **2 种模式 × 18 种取色 = 36 组组合**（含中灰 / 纯黄 / 纯白 / 纯黑 / 暗红 / 荧光绿 / 深灰等极端值），按钮字、气泡字、正文对比度**全部 ≥ 4.5:1**。

### 特效

- **切换扩散动画**：从点击位置用 `clip-path: circle()` 扩开一整屏（渐变在 CSS 里不可过渡，用圆形裁剪更便宜）。
- **背景光晕流动**：三个光斑以 29 / 34 / 41 秒各自漂移；因为玻璃后面一直在变，透过玻璃看到的颜色也在极缓慢变化。
- **呼吸辉光**（品牌标记）与**思考点脉动**。

光晕流动与扩散动画**都可以关掉**：玻璃后方持续变化会让 iOS 不停重算模糊层、增加耗电。

### 无障碍与实现细节

- 系统开启 `prefers-reduced-motion` 时特效自动失效。选择器必须写成 `*, *::before, *::after` —— **`*` 只匹配元素、匹配不到伪元素**，否则呼吸辉光、脉动、流式光标在"减弱动态效果"下仍会继续动。
- `color-scheme` 按模式**显式声明**：它决定原生控件（下拉框、滚动条、颜色选择器）与画布默认底色的渲染，不声明会退成 `normal`，深色主题下原生控件会渲染成浅色。
- 浅色模式是**追加的覆盖层**（`html[data-mode="light"]`），完全不改深色模式的既定行为。
- 主题与模式存在 `localStorage`，刷新后保留。
- 品牌图形（Logo / 头像）的 `fill` 由 CSS 覆盖并加了过渡，换色时是渐变而不是跳变。

## 界面：液态玻璃

深色主题随应用图标配色（深海军蓝 + 青绿），设计 token 集中在 `styles.css` 顶部的 `:root`。

**玻璃效果要成立，有两个前提，缺一不可：**

1. **后面必须有东西可折射。** 所以顶栏与输入区是固定层（`position: fixed`），消息从它们**底下滚过去**。如果它们只是消息区的兄弟元素，`backdrop-filter` 只会模糊到纯色背景 —— 看起来是玻璃，实际什么都没模糊。
2. **必须有方向光。** 镜面高光写在元素自身的 `background-image` 里（**不能**用 `::before` 叠加，绝对定位伪元素会盖在文字上把文字冲淡）；边缘用遮罩做成 1px 渐变环 —— 左上最亮、中间最暗、右下回亮，这是"折"出来的边：

```css
.glass::after {
  padding: 1px;
  background: linear-gradient(150deg, rgba(255,255,255,.58), …);
  -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite: xor; mask-composite: exclude;
}
```

**几个刻意的取舍：**

- **消息气泡不用 `backdrop-filter`。** 滚动列表里逐条模糊会明显掉帧，所以气泡改用同样的"方向光 + 高光"配方做出玻璃质感，代价接近零。真正需要通透感的只有顶栏、输入区、面板与菜单。
- **背景层是静止的。** 持续动的背景会让 iOS 不停重算模糊层、很耗电。玻璃的"液态"感来自方向光、镜面高光、多层半透明与按压反馈，而不是动画。
- **输入区比顶栏实。** 它背后是用户正在读的正文，透太多会干扰输入；另外顶栏下方、输入区上方各有一道渐隐遮罩，内容接近时淡出（iOS 常规做法）。
- **留白由 JS 实测回填。** 顶栏/输入区高度会变（输入框长高、附件条出现），写死数值一定会错位，所以用 `ResizeObserver` 实时写入 `--topbar-h` / `--dock-h`。
- **降级**：浏览器不支持 `backdrop-filter`，或系统开启"减弱透明度"时，自动退化为不透明面板，避免文字糊在背景上。

> **Safari 做不到真正的折射。** `backdrop-filter: url(#svg-filter)`（用 `feDisplacementMap` 做真实折射扭曲）**Safari 不支持**，只有 Chrome 支持。所以这里用的是"高光 + 方向光边 + 多层半透明"的近似，而不是真正的液态折射。

其他细节：

- **强调色只用在可点击处**。亮青（`#12c4c9`）配深色字对比度约 7.6:1，用于发送键等按钮；用户气泡用深青渐变承载正文，因为亮青上放白字只有约 2.9:1，读不清（实测 5.63:1）。
- **代码块带语言标签与复制按钮**，复制走事件委托，流式输出中途已渲染的代码块也能立刻复制。
- **支持表格、引用、分隔线**：窄屏下已收紧字号与内边距让 4 列放得下。
- **提示条设了 `pointer-events: none`**：它浮在消息上方，绝不能拦住下面按钮的点击。
- 尊重 `prefers-reduced-motion`。

## 部署到 GitHub Pages

1. 把这些文件提交到仓库根目录（分支 `main`）。
2. **Settings → Pages** → Source 选 `Deploy from a branch` → Branch 选 `main` → 目录 `/ (root)` → Save。
3. 等构建完成后打开 `https://<用户名>.github.io/<仓库名>/`。

## 在 iPhone 上安装

1. 用 **Safari** 打开该网址（必须 Safari，Chrome 无法添加到主屏）。
2. **分享 → 添加到主屏幕**。
3. 从主屏启动，全屏运行。

## 填入 API Key（必做）

点右上角设置图标，填入 DeepSeek API Key（[在此创建](https://platform.deepseek.com/api_keys)），再点「测试连接」。

**关于 Key 的安全性：**

- 本仓库是**公开**的。Key 只存在你手机浏览器的 localStorage 里，**不会上传，也不会写进任何文件**。
- 因此**绝对不要**把 Key 写进 `app.js`、`README.md` 或任何提交的文件里——一提交就等于公开泄露。
- 应用不经过任何第三方服务器：浏览器直接请求 `https://api.deepseek.com`。

## 图片输入

支持三种来源：**拍照**、**相册**、以及截图后从相册选。iOS 的 HEIC 照片会在本地转成 JPEG。

**发送前会在本机降采样到长边 1568px**，原因有两个，都是硬限制：

- 接口要求单图最长边不超过 8192px，且请求体上限 **48 MiB**；iPhone 原图 3–5 MB，base64 后膨胀约 33%，几张原图就会把请求撑爆。
- 服务端反正会把图片压到约 1300×1300（每图最多计 1024 token），发原图纯属浪费流量和 token。

实测：一张 2400×1600 / 1.2 MB 的图，发出时是 1568×1045 / 57 KB，整条请求体 76 KB。

**只有 `deepseek-flash` 支持图片**。选中 `deepseek-v4-pro` 时若已附图片，应用会提示并询问是否切换模型。

## 文档读取

点输入框左侧的 `+` → 「选择文档 / 代码文件」，通过 iOS「文件」App 从 iCloud Drive 或「我的 iPhone」中选取。

| 类型 | 支持情况 |
|---|---|
| txt / md / json / csv / 各类代码文件 | ✅ 直接读取 |
| **.docx** | ✅ 用 `DecompressionStream` 解 ZIP 读 `word/document.xml`，**零外部依赖** |
| **.pdf** | ⚠️ 简易提取（解 FlateDecode 流抓 Tj/TJ 字符串）。简单 PDF 可用；**使用中文 CID 字体的 PDF 常提不出干净文本** |
| 其他二进制格式 | ❌ 会明确提示不支持 |

**解析结果一律先弹出预览让你确认**，不会偷偷把内容发出去。提取质量差时预览里会标出 ⚠️ 和具体原因。如果 PDF 预览是乱码，**改用截图 → 相册选图**这条路，靠视觉能力读，比提取文本可靠得多。

## 把生成的代码存回手机

浏览器**不能写手机的文件系统**。唯一的出口是系统分享面板：AI 回复里的代码块可以点「存为文件」，走 `navigator.share({files})`，在分享面板里选「存储到文件」即可存进「文件」App。若浏览器不支持分享文件，则退化为下载。

回复里有多个代码块时会让你选序号，不会替你猜。

## 权限：真实能力与硬边界

设置面板里的「权限」区展示的是**浏览器真实权限状态**（相机 / 麦克风 / 通知 / 持久存储），可逐个申请。

**这里没有、也不会有"完全权限"开关**——因为网页应用运行在浏览器沙箱里，给了也拿不到东西：

| 你想要的能力 | 网页应用能否做到 |
|---|---|
| 读取你**主动选中**的文件 | ✅ 可以 |
| 读取**任意**手机文件（不用你选） | ❌ 沙箱禁止 |
| 把文件写回手机文件系统 | ❌ 浏览器不允许（只能走分享面板） |
| 执行命令 / 跑 shell | ❌ 没有 |
| 在手机上运行代码 | ❌ 无解释器（WASM 除外，且读不到真实文件） |
| 控制手机 UI（computer-use） | ❌ 需要原生辅助功能 API |
| 后台常驻、开机自启 | ❌ 网页做不到 |

**需要真正的全权限 agent / computer-use，唯一的路是让手机远程连接你电脑上运行的 DSH**——工具在电脑上执行，手机只当屏幕。注意 DSH 出于安全考虑**刻意禁止**了 `--host 0.0.0.0`（会向网络暴露远程代码执行），官方留下的口子是 loopback 绑定 + TLS 反向代理或 tunnel（`--trusted-host` 就是为此设计的），例如 Tailscale。

## 模型与参数

| 模型 | 特点 |
|---|---|
| `deepseek-flash` | DeepSeek-V4.1-Flash，快，1M 上下文，**支持图片** |
| `deepseek-v4-pro` | DeepSeek-V4-Pro，推理更强，**不支持图片** |

思考模式：`thinking: {"type": "enabled" | "disabled"}`，强度用 `reasoning_effort`（`low` / `high` / `max`），默认开启且为 `high`。

思考模式下 `temperature`、`presence_penalty`、`frequency_penalty` 均**不生效**（发了也会被静默忽略），所以本应用不提供这些设置。

## 文件说明

| 文件 | 作用 |
|---|---|
| `index.html` | 页面结构 |
| `styles.css` | 样式（含 iOS 安全区适配） |

## 已知限制

- **没有工具能力**：不能读写你的文件、不能执行命令。本应用只是手机端聊天界面。
- **pdf 提取对中文 PDF 不可靠**，见上文，建议改走截图 + 视觉。
- **文档一次处理一个**（会提示），不支持批量。
- 图片与文档正文存在 IndexedDB，localStorage 只存引用；但会话很多时仍建议清理旧会话。
- 语音输入尚未接入（麦克风权限已可申请，但没有接语音识别）。
- **改任何应用文件后，必须把 `sw.js` 里的 `CACHE` 版本号 +1**，否则老用户会被 Service Worker 的缓存锁在旧版本上。
